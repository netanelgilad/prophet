# P042 independent read-prefix design review

Recommendation: approve the narrow fresh POSIX TCP read-initiation prefix, subject to the guards and evidence below. This is a read-only source/design assessment, not implementation acceptance. At this writing the proposed `design.md` and `native-read-findings.md` have not yet appeared; this assessment uses the pinned source files and `read-probe.cjs`/`read-results.json` directly.

## Justified transition

Pinned Node v24.21.0 `lib/net.js:1963–2015` emits connect then ready, dynamically calls isPaused, then read(0) if the retained callback readable flag is true and the socket is not paused. For the admitted fresh, empty, constructed readable stream, `lib/internal/streams/readable.js:655–797` sets reading=true, sync=true, needReadable=true, calls _read(highWaterMark), clears sync, returns null. It does not consume bytes or emit data/readable/end, schedule resume/end/maybeReadMore, or refresh the timer. The native fixture independently records the exact flags before/during/after this prefix, including end-pending, and callback throws preventing the later stages.

`Socket._read` (`net.js:994–1014`) sets handle.reading=true then calls readStart. `src/stream_base.cc:151–153` and `src/stream_wrap.cc:201–214` directly call uv_read_start. `deps/uv/src/uv-common.c:922–937` rejects only null stream/callbacks, closing, already reading, or not readable. These are excluded by the original live fresh handle, full readable completion, no earlier read, and supported callback domain. `deps/uv/src/unix/stream.c:1447–1469` registers desired reading and callbacks/watchers, then returns 0; no read or allocation callback occurs synchronously. P041 pending shutdown clears writable, not readable, and therefore does not invalidate this derivation. Do not invent a fresh readStart-success Boolean or inject generic EIO into the admitted fresh domain. Generic injected failure native controls illustrate broader compatibility only. The io-watcher helper may internally encounter allocation/backend issues; a return of zero is not proof that future OS reading succeeds, and existing native allocation/process-failure gaps remain.

## State and domain obligations

Retain a persistent owned readable/handle-start record, initialized at socket creation, rather than a success marker added only at completion. At minimum the modeled state must distinguish constructed=true, sync=true, length=0, reading=false, needReadable=false and handleReading=false initially, then reading/needReadable/handleReading=true and sync=false after the prefix. The scope also relies on empty/no EOF/no error/not destroyed, flowing=null, paused=false, emittedReadable=false, endEmitted=false, readableListening=false, resumeScheduled=false and readingMore=false. These may be explicit state or documented invariants protected by the admitted API domain. POSIX default byte highWaterMark is 65536; its mutable `stream.setDefaultHighWaterMark` route remains unsupported. If public readable fields are exposed, verify their values at queued, submitted, failed/partial completion, shutdown-pending and queued-destroy phases; destruction makes readable false while it does not imply EOF/endEmitted.

After connect and ready callbacks, recheck the live socket/prototype/readable domain before changing read state. Initial completion validation is insufficient. Preserve callback writes/effects on stopped branches. Original dynamic isPaused/read/_read and relevant Object/Function prototype dependencies must be established or stop; conditional mutation must not contaminate a healthy sibling. Unsupported method lookup/replacement must not become an accidentally admitted arbitrary public read API just because the internal prefix needs it. Keep pause/resume, data/readable registration, raw handle/state access and arbitrary public read overloads outside this increment. The native readable/data-listener controls demonstrate why widening only the event-name allowlist is wrong: those registrations can schedule earlier reads and change flowing/paused/reading state. A callback may validly create another resource or perform P041 end; neither should alone fail the fresh readable domain.

## Completion, queue and proof requirements

Only after the complete supported prefix returns normally may external.active clear and the shared afterEvent nextTick drain run. A typed stop after either callback keeps active delivery and the callback/read frontier; a guest throw follows existing throw cleanup and must not run ready/read or queued jobs as if normal. No synthetic nextTick event should represent readStart. Preserve the actual completion and readStart receiver/activation, current timer-arm identity and shutdown-pending state. A stopped nextTick after normal completion must show external.active cleared, distinguishing it from a stopped callback while delivery remains active.

Required independent probes: (1) exact before/during/after readable state, once identity and unchanged timer; (2) end in connect/ready still reaches readStart and a normal handler return; (3) callback throw/typed stop prevents later stages; (4) prototype mutation in both callback positions, including a conditional healthy sibling, stops before read mutation; (5) resource created in a callback is submitted by nextTick only after the first handler returns; (6) two independent sockets and mixed HTTP/TCP event horizons 0/1/2, with completion facts stable, consumption one-shot and waiting alternatives retained; (7) unknown/partial completion branches remain stopped and cannot reach readStart; (8) normal completion followed by queued-job stop preserves an idle external checkpoint. Existing finite-record-choice regressions must remain green.

The returned normal history means this callback prefix completed. It does not prove peer availability from checkGrowl beyond that callback, receipt of data, successful shutdown/flush, absence of later timeout, EOF/error/close, quiescence, or full event-loop coverage. The unchanged external horizon excludes timer/data/shutdown/close delivery; document these missing interleavings as residual limitations. No new arbitrary resource cap appears needed for this constant-size transition, but existing unbounded graph/acquisition and callback recursion gaps are unchanged.

## Final-contract cross-check — approved

Read the completed design and native findings in full. They satisfy the conditions above: guarded fresh readable state, deterministic source-derived binding return, unchanged writable/timer facts, post-ready intrinsic revalidation, no public read-domain expansion, and normal generic external cleanup followed by real queued jobs. The design correctly includes the Socket.read wrapper's dynamic Duplex.prototype.read.call dependency (pinned net.js:1067), so Function.prototype must be revalidated even though Readable.read itself calls _read directly. Keeping public readable getters unsupported avoids introducing unverified values in failed/partial/destroyed phases. No remaining design blocker found. This approves the proposed contract, not an unreviewed implementation.

The native findings distinguish controlled binding injection from the POSIX source proof, classify EIO/pause/data/readable controls outside the admitted domain, and avoid claiming native package/transport execution. The watcher-capacity argument strengthens but does not replace the narrower return-value proof. Current queue/microtask/timer/data/shutdown gaps remain explicit. Required implementation tests in the design cover the substantive obligations; add or retain the queued-job typed-stop versus active-callback typed-stop checkpoint distinction described above.
