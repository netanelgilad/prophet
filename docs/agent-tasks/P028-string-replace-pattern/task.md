# P028: String.prototype.replace with concrete string search values

Implemented by Instinct in-sandbox; independent review pending.

## Goal

The sirv range parse is
`req.headers.range.replace('bytes=', '').split('-')` (build.js:73). The
existing replace model (P016) covered only intrinsic-layout flagless/g
RegExp no-match identity; a string search value stopped as a typed
boundary. This task lands the string search slice.

## Decision record

Pinned Node 24.21.0 matrix: a string search value is literal (no pattern
semantics) and replaces only the first occurrence; a missing occurrence is
the identity; an empty search inserts at position zero. The replacement
string applies GetSubstitution: `$$` escapes a dollar, `$&` is the matched
string, `$`` the text before the match and `$'` the text after it;
with no capture groups, `$n` and `$<name>` stay literal, as does a trailing
`$`. Number/undefined replacement values ToString-convert natively and
function replacements observe the match, so both stay typed boundaries, as
do non-string search values (numbers convert natively) and custom
Symbol.replace dispatch.

Implementation extends the P016 slice in src/string/replace.ts inside the
existing receiver-conversion flow: after ToString of the receiver, a
concrete ESString search value takes indexOf over the concrete text, and a
concrete ESString replacement expands through a bounded GetSubstitution
helper. The boundary ordering matches the spec rows: non-string search
values, function replacements and non-string replacement values each stop
with their own typed boundary.

Specs first: ten new tests in test/string-replace.spec.ts (every expected
value generated by the pinned Node oracle, never written from memory):
first-occurrence, no-match identity, empty search at position zero, literal
search characters, the four substitution forms at the match position,
literal $n/$</trailing-$, and the three typed boundaries. Honest migration:
the P016 boundary table's string-search row moved to the new non-string
search boundary (`"a1c".replace(1, "-")`).

Validation (sandbox, Node 24.21.0, PROPHET_NODE_BINARY pinned): full suite
and typecheck on the shipped tree (totals in the ledger); string-replace
suite green individually.

## Frontier after P028

Sirv range requests still need the parseInt global, header-carrying
deliverRequest input, and createReadStream {start,end} option fields.
Function replacements, non-string conversions, RegExp match observation and
Symbol.replace dispatch remain replace gaps.
