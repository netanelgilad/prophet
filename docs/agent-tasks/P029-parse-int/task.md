# P029: the parseInt global over concrete inputs

Implemented by Instinct in-sandbox; independent review pending.

## Goal

The sirv range parse reads `parseInt(y, 10) || stats.size - 1` and
`parseInt(x, 10) || 0` (build.js:74-75). parseInt was an absent global, so
the range path could not dispatch. This task lands the global; the range
wire case still needs header-carrying deliverRequest input and
createReadStream {start,end} options.

## Decision record

Pinned Node 24.21.0 matrix: leading whitespace and an optional sign precede
digits; trailing garbage ends the parse; no parseable digits yields NaN.
Auto radix (0 or omitted) is decimal except a 0x/0X prefix after the sign,
which selects 16 and is consumed; an explicit radix of 16 also permits the
prefix. "0b11" parses as 0 (b is not a digit), "08" is decimal 8, and
out-of-range radices (1, 37) yield NaN while fractional radices truncate
(10.9 behaves as 10). Large integers round to the nearest double
(parseInt("9007199254740993") === 9007199254740992). Native ToString of
non-string inputs and ToNumber of non-number radices (a string "10" radix
works natively) stay typed boundaries.

Over concrete inputs the digit semantics are total, deterministic and
spec-stable, so the implementation delegates them to the pinned host's
parseInt - the same convention the escape-sequence scanner already uses
(src/ASTResolvers.ts) - after branching symbolic inputs through withValue.
The global object mirrors the builtin-function metadata pattern: pinned
length 2 and name "parseInt", boundary-marked metadata.

Specs first: ten pinned-oracle tests in test/parse-int.spec.ts covering
decimal/whitespace/sign/garbage, NaN identity (guest-side `r !== r`, since
the VM models NaN as a concrete number), auto and explicit radix prefix
rules, radix truncation and range failures, the omitted-radix path, double
rounding, metadata, and the two typed boundaries. Every expectation is
generated by the pinned Node oracle, not written from memory.

Validation (sandbox, Node 24.21.0, PROPHET_NODE_BINARY pinned): full suite
and typecheck on the shipped tree (totals in the ledger); parse-int suite
green individually.

## Frontier after P029

Sirv range requests end to end: header-carrying deliverRequest input and
createReadStream {start,end} option fields. Non-string parseInt inputs and
non-number radices (ToString/ToNumber conversions) remain gaps alongside
the other absent globals in LIB-001.
